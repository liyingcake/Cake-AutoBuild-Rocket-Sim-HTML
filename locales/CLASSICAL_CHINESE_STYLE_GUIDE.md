# Rocket SIM「文言-华夏」本地化规范

## 一、定位

「文言-华夏」是 Rocket SIM 的架空历史语言变体，语言标识为
`zh-Hans-x-classical`，显示名称为“文言-华夏”。

本变体采用：

- 简体汉字字形；
- 浅近文言句法；
- 唐代格物、算学、军器与天文语感；
- 原有阿拉伯数字、单位、公式、材料牌号与型号。

设想盛唐已有火箭工程之学，一位通晓算经、浑仪、营造与火器的学者正在使用此器。
目标是营造可信的架空古代学术氛围；在不破坏数值操作的前提下，文采与时代感高于
现代术语的逐字严谨。

## 二、转换层级

翻译按下列优先级执行：

1. **稳定消息键**：告警、确认、状态、自动名称等动态内容须使用消息键。
2. **实体 ID**：天体、推进剂、材料、工艺、循环、预设型号等按稳定 ID 提供显示字段。
3. **完整界面句**：按钮、标题、说明和帮助文字优先整句翻译，不拼接零散字词。
4. **兼容词组表**：只用于尚未迁移的旧静态节点；长词先于短词。
5. **创造性转译**：无史成词者，可依字义、器用和唐人学术语感造词。
6. **文言回退**：无可靠专名时，至少改写句法与虚词，不整段回退白话。

## 三、世界观与造词法

本语言并非考据复原，而是“若唐人已有现代航天知识，将如何为其命名”的架空转译。

造词依下列途径：

1. **取其功用**：发动机称“推进机”，喷管称“喷焰管”，航电称“飞控仪电”。
2. **取其形制**：储箱称“贮剂舱”，级间称“承接段”，整流罩称“御风罩”。
3. **取其物理**：推力称“进力”，推重比称“进力重比”，动压称“疾风压”。
4. **取其工艺**：增压称“益压”，节流称“节焰”，屈曲称“压曲”。
5. **借古代学术语**：计算称“演算”，模型称“法式”，参数称“诸元”，验证称“验算”。
6. **双名并列**：难以识别者首次可写“天速增量（Δv）”“最大疾风压（Max Q）”。

造词须前后一致；同一概念不得在一页内出现多个古称。

## 四、文体原则

### 3.1 句式

- “请选择……”写作“请选择……”或“宜择……”，不使用生僻倒装。
- “开启后……”写作“启之，则……”。
- “如果……则……”写作“若……，则……”。
- “用于……”写作“以……”或“所以……”。
- “不支持/不能……”写作“不可……”。
- “已经……”写作“已……”。
- “仍然……”写作“犹……”。
- “需要……”写作“须……”。
- “建议……”写作“宜……”。
- “检查……”写作“察……”或“校核……”。

短按钮以二至四字为宜，例如：

| 现代中文 | 华夏古文 |
|---|---|
| 保存方案 | 存此案 |
| 恢复默认火箭 | 复归初制 |
| 导入 | 纳入 |
| 导出 JSON | 导出 JSON |
| 上一步 | 前一步 |
| 下一步 | 后一步 |
| 暂停 | 暂止 |
| 继续 | 续行 |
| 复位 | 复初 |

### 3.2 人称与语气

- 系统不用“您”，采用无主句。
- 普通说明用平叙语气。
- 警告用“慎”“警”“须察”开头。
- 错误用“不可”“越限”表明后果。
- 可使用“其、之、若、则、宜、须、乃、故、未、已、犹”等浅近虚词。
- 可有适度骈句与格物口吻，但不得妨碍按钮和告警的含义。
- 段落宜改写整句，不以逐词替换拼出残破语序。

### 3.3 标点

- 使用现代中文标点，保证长技术说明可读。
- 参数之间保留 `·`、`/`、`→`。
- 模板变量继续使用 `{name}`、`{count}` 等形式。

“火药”，亦不得改变任何计算键、单位与化学式。

## 六、数字、单位与专名

- 数值一律使用阿拉伯数字。
- 倒计时语音可使用“一、二、三……十”。
- SI 单位和符号保持原样：`kg`、`m`、`s`、`kN`、`MPa`、`K`。
- 货币格式保持 `¥` 与现有倍率。
- 火箭型号保持正式名称：V-2、Saturn V、Soyuz、Fregat、长征五号。
- 材料牌号保持原样：304L、Al 2219、Inconel 718、GRCop-42。
- 化学式保持原样：LOX、LH2、NTO、MMH、UDMH。

## 七、动态消息模板

动态句不得依靠文本切片翻译，须保留完整模板。例如：

```text
现代：损失一台发动机后推重比为 {twr}，不足以保留 {margin} 的继续上升裕度。
古文：若损一发动机，推重比为 {twr}，不足存 {margin} 之续升余裕。
```

模板两种语言的占位符集合必须完全一致。

自动方案名可随语言切换重新生成；用户手动输入名称和已保存名称不得转换。

## 八、实体字段

实体以稳定 ID 对应翻译，不修改计算键和数值。例如：

```js
entities: {
  celestialBodies: {
    earth: { name: "地球", atmosphere: "氮氧大气" }
  },
  cycles: {
    "gas-generator": { name: "燃气发生器循环", complexity: "中" }
  }
}
```

专有实体名称本身可保持现代中文；描述、类别和状态可按本规范古文化。

## 九、语音

- 语音语言使用 `zh-CN`，以获得较稳定的中文语音。
- 倒计时使用“一”至“十”。
- 找不到中文语音时交由浏览器默认语音。

## 十、质量检查

每次修改须检查：

- 动态消息键与现代中文语言包一致；
- 模板占位符一致；
- `html lang` 更新为 `zh-Hans-x-classical`；
- 语言选择可持久化；
- 数值结果、配置序列化和动画状态不随语言改变；
- 不把语言写入设计 JSON；
- 界面不得出现乱码；
- 文言模式的主要页面须达到高比例古文化，不得大段保留现代白话。
- 不得出现因短词替换造成的残破语序；常见长句必须使用整句映射。
- 同一工程实体的古称须一致。

## 十一、新增文案流程

1. 先在现代中文语言包登记稳定键。
2. 按本规范写古文完整句。
3. 若涉及实体，按实体 ID 增加字段。
4. 为占位符、回退和数值不变性增加测试。
5. 旧静态页面可暂用完整原文映射，后续迁移为 `data-i18n`。
